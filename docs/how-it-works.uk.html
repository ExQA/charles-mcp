charles-mcp · мобільне QA

Як агент читає трафік застосунку і підміняє відповіді

Charles записує трафік телефона. MCP-сервер читає ту саму сесію і кладе на диск правила, за якими відповідь приходить уже зміненою — без перезбирання застосунку і без правок на бекенді.

Застосунок→Charles :8888→диспетчер :18080→сервер

Перехоплення: дві площини

Трафік застосунку і робота агента — це два різні шляхи до одного Charles. Застосунок ходить через проксі, агент читає сесію через Web Interface. Агент ніколи не перехоплює трафік сам.

Три джерела відповіді

Один і той самий запит застосунку може бути обслужений із трьох місць. Заголовок у відповіді завжди каже, звідки вона прийшла — це і є перевірка, що мок спрацював.

Коли вистачає Map Local

Один URL — одна відповідь, зазвичай GET. Charles віддає файл сам, окремий процес не потрібен.

Коли потрібен диспетчер

Один URL відповідає по-різному залежно від поля тіла, потрібен код помилки, затримка або правка запиту.

Що вміє одне правило

Правило — це JSON-файл у каталозі моків поза репозиторієм. Диспетчер перечитує його на кожен запит, тому правка діє одразу, без перезапуску Charles.

Правка знаходить елемент за полем

// баланси приходять у різному порядку,
// тому індекс /balanceList/1 — пастка
{
  "op": "set",
  "path": "/data/balanceList/[currency=USD]/balance",
  "value": "1000.00"
}

Шлях не прибитий до платформи

// один запис правила на Android і iOS
"match": {
  "method": "POST",
  "path": "/api/*/wallet",
  "body": { "/action": "init" }
}

Налаштування Kiro

Kiro запускає MCP-сервер по stdio сам. Конфіг кладеться у проєкт або до користувача; за розбіжності виграє проєктний.

  1. Увімкнути Web Interface у Charles

    Proxy → Web Interface Settings: позначити Enable web interface, задати свої логін і пароль. Allow anonymous access не вмикати — через цей інтерфейс читається вся сесія.

  2. Підключити пристрій і сертифікат

    • На телефоні: проксі Wi-Fi → IP комп'ютера, порт 8888.
    • У Charles дозволити пристрій: Proxy → Access Control Settings.
    • Proxy → SSL Proxying Settings — додати хости API, на пристрій поставити сертифікат Charles і довірити його.

    Без цього кроку інструменти бачитимуть тільки хости без шляхів.

  3. Поставити форк

    Пакет у PyPI — це upstream без інструментів моків, тому ставимо з репозиторію команди.

    git clone https://github.com/ExQA/charles-mcp.git
cd charles-mcp
uv sync --locked --extra dev
uv run python -m pytest -q

  4. Додати сервер у конфіг Kiro

    Проєктний файл .kiro/settings/mcp.json або користувацький ~/.kiro/settings/mcp.json. Якщо файл уже є — додати ключ charles всередину mcpServers, не затираючи інші сервери.

    {
  "mcpServers": {
    "charles": {
      "command": "uv",
      "args": ["run", "--project", "/Users/you/Projects/charles-mcp", "charles-mcp"],
      "env": {
        "CHARLES_USER": "ваш-логін",
        "CHARLES_PASS": "ваш-пароль",
        "CHARLES_MANAGE_LIFECYCLE": "false"
      },
      "disabled": false,
      "autoApprove": ["charles_status", "start_live_capture",
                      "query_live_capture_entries", "group_capture_analysis"]
    }
  }
}

    Шлях у --project — абсолютний. CHARLES_MANAGE_LIFECYCLE=false тримає Charles під вашим контролем: сервер не закриє його сам.

  5. Перевірити зв'язок

    Зберегти файл — Kiro перепідключить сервер, у панелі MCP він має стати активним. Далі попросити агента викликати charles_status: у відповіді буде зв'язок із Charles і підказка наступного кроку.

  6. Завести маршрут під моки

    Один раз на домен. Правило Map Remote пишеться у конфіг Charles, а він перезаписує конфіг із пам'яті під час виходу — тому запис можливий лише при закритому Charles.

    • mock_route_setup(host="*.example.com", path="/api/*") без apply — агент віддасть кроки для UI, вони діють одразу після Done.
    • З apply=true — зберегти сесію, закрити Charles, дати агенту записати правило, запустити Charles.
    • Далі mock_dispatcher(action="start") — підніме диспетчер і ввімкне Map Remote.

Що не давати на автоапрув

reset_environment закриває Charles і видаляє збережені записи. mock_setup_host і mock_route_setup з apply=true пишуть конфіг Charles. reverse_replay_entry і правила в режимі patch відправляють справжні запити зі справжніми токенами. Ці виклики варто підтверджувати руками.

Два правила, які економлять час

Charles читає конфіг під час запуску і перезаписує його з пам'яті під час виходу: правка конфіга при запущеному Charles просто зникне. Натомість моки і правила диспетчера — це дані на диску, вони перечитуються на кожен запит і перезапуску не потребують.

Кожен live-запит вивантажує всю сесію Charles. Перед сценарієм сесію варто очистити, інакше інструменти гальмують на гігабайтах трафіку.

Деталі та контракт кожного інструмента — у репозиторії команди: docs/agent-guide.uk.md, docs/charles-mapping.uk.md, docs/contracts/tools.uk.md.
