# Як працює мапінг і коли перезапускається Charles

> English version: [charles-mapping.md](charles-mapping.md)

Документ описує, як моки charles-mcp вбудовуються в Charles, які дії потребують перезапуску Charles, як виконати його безпечно і що робити, якщо правило не спрацьовує. Усе нижче перевірено на Charles 5.2.1 (macOS), якщо не сказано інше. Обґрунтування рішень — в [ADR-0001](adr/0001-data-driven-body-aware-mocks.uk.md).

## 1. Схема

```
Застосунок ──► Charles ──┬─ Map Local:  https://<host>/*  ─► файл ~/charles-mocks/<host>/<шлях>
                         │                                   (файлу немає → справжній сервер)
                         │
                         └─ Map Remote: https://*.домен/api/* ─► диспетчер 127.0.0.1:18080
                                        (preserve host header,     │
                                         порожній шлях призначення)├─ правило fixture → відповідь з файлу, будь-який статус
                                                                   ├─ правило patch   → справжній сервер, правка запиту й відповіді
                                                                   └─ правила немає   → справжній сервер без змін
```

Два механізми, обирайте за ендпоінтом:

| | Map Local | Map Remote + диспетчер |
|---|---|---|
| Коли | відповідь не залежить від тіла запиту (зазвичай GET) | один URL, різні відповіді за полем тіла (`action`), потрібен статус не 200 або правка запиту, багато шляхів і хостів |
| Правило в Charles | одне на хост | одне на домен (шаблон хоста) |
| Моки | файли `~/charles-mocks/<host>/<шлях>` | правила і фікстури в `~/charles-mocks/_rules/` |
| Статус відповіді | завжди 200 | будь-який |
| Чи потрібен процес | ні | диспетчер має працювати |
| Перевірка | заголовок `X-Charles-Map-Local` | заголовок `X-Charles-MCP-Rule` (id правила або `passthrough`) |

## 2. Що Charles вміє і чого ні

- Правила Map Local, Map Remote і Rewrite **не можна міняти на льоту** ззовні. Web Interface (`http://control.charles`) вміє лише вмикати й вимикати інструмент цілком, керувати записом і сесією та закривати Charles.
- Charles **читає конфіг під час запуску** і **під час виходу записує конфіг з пам'яті**. Правка файлу при запущеному Charles не просто не застосується — її буде затерто на виході.
- Жоден інструмент Charles не вміє умову за **тілом запиту**. Rewrite з регулярними виразами міняє поле в усіх відповідях URL, але не може зробити це лише для `action=init`. Тому варіанти за `action` розрізняє диспетчер.
- Тому в Charles ставиться **одне статичне правило**, а все, що змінюється, — дані: файли Map Local і правила диспетчера. Їх можна міняти будь-коли без перезапуску, Charles і диспетчер перечитують їх на кожен запит.

## 3. Коли потрібен перезапуск Charles

| Дія | Перезапуск | Як |
|---|---|---|
| Створити, змінити, видалити мок-файл Map Local | ні | `mock_create_from_entry`, `mock_write`, `mock_remove` |
| Створити, змінити, вимкнути правило диспетчера | ні | `mock_rule_create_from_entry`, `mock_rule_set_enabled`, `mock_rule_remove` |
| Увімкнути або вимкнути Map Local | ні | `mock_set_enabled` (через Web Interface) |
| Увімкнути або вимкнути Map Remote | ні | `mock_dispatcher(action="start" / "stop")` робить це сам |
| Завести правило Map Local для нового хоста | **так**, або вручну в UI | `mock_setup_host(apply=true)` або кроки з `mock_setup_host()` |
| Завести правило Map Remote для нового домену | **так**, або вручну в UI | `mock_route_setup(apply=true)` або кроки з `mock_route_setup()` |

Правило в Charles ставиться **один раз на хост або домен**. Після цього перезапуск не потрібен, доки не з'явиться новий домен.

**Активує мапінг саме запуск.** Charles читає конфіг лише під час старту, тому мапінг Map Remote, записаний через `apply=true`, не робить нічого, доки користувач не запустить Charles — і файл на диску, і вікно Map Remote при цьому виглядають правильно. Після запуску перевірте це через `mock_dispatcher(action="verify")`, а не проханням до користувача ще раз потикати застосунок.

Якщо перезапуск небажаний (триває важлива сесія), правило можна додати вручну в UI Charles — це працює без перезапуску і застосовується одразу після **Done**.

## 4. Як проходить перезапуск

Інструменти charles-mcp **самі Charles не закривають і не запускають**. `apply=true` лише записує конфіг і відмовляється це робити, якщо Charles запущений (перевіряється порт проксі). Порядок такий:

1. **Збережіть сесію, якщо вона потрібна** (File → Save Session). Під час виходу Charles незбережена сесія зникає.
2. **Закрийте Charles** (Charles → Quit). Агент з вашого дозволу може зробити це сам через Web Interface (`http://control.charles/quit`).
3. **Не відкривайте Charles**, доки агент не повідомить, що правило записане. Якщо Charles відкриється раніше, запис не відбудеться (інструмент відмовиться), а якщо відкрити його між перевіркою і записом — правку буде затерто під час наступного виходу.
4. Агент викликає `mock_route_setup(host="*.домен", path="/api/*", apply=true)` або `mock_setup_host(host, apply=true)`. Перед записом робиться бекап конфіга.
5. **Запустіть Charles.** Правило завантажиться під час старту.
6. `mock_dispatcher(action="start")` — запускає диспетчер і вмикає Map Remote.

Перевірити, що Charles прийняв правило: Tools → Map Remote, правило є в списку з галочкою. Charles під час наступного виходу перезбереже його у своєму форматі (наприклад, прибере `<enabled>true</enabled>` як значення за замовчуванням) — це нормально.

### Бекапи і відкат

Перед кожним записом конфіг копіюється в `~/Library/Application Support/charles-mcp/charles-config-backups/<map-remote|mock-setup>/com.xk72.charles.config.<час>` (на Windows і Linux — каталог стану charles-mcp, змінна `CHARLES_STATE_DIR`). У бекапах ліцензійний ключ і облікові дані Web Interface — не передавайте їх.

Відкат: закрийте Charles, скопіюйте потрібний бекап поверх `~/Library/Preferences/com.xk72.charles.config`, запустіть Charles. Простіше і без перезапуску — видалити правило в UI (виділити, «−», Done).

## 5. Правило Map Remote у деталях

`mock_route_setup` записує (або видає для ручного введення) таке правило:

| Поле | Значення |
|---|---|
| From: Protocol / Host / Port / Path | `https` / `*.домен` або хост / `443` / `/api/*` (або `/*`, або один шлях) |
| To: Protocol / Host / Port / Path | `http` / `127.0.0.1` / `CHARLES_DISPATCHER_PORT` (18080) / **порожньо** для шаблону шляху |
| Preserve host header | **увімкнено** — без нього диспетчер не дізнається вихідний хост |

Перевірено наживо:

- шаблон хоста `*.example.com` ловить `www.example.com`;
- за порожнього шляху призначення шлях доходить до диспетчера без змін (`/api/wallet`, `/api/deep/other/path?x=1`);
- запити поза `/api/*` (наприклад `/index.html`) не мапляться і йдуть на сервер як звичайно;
- з «Preserve host header» диспетчер отримує вихідний `Host`, знаходить маршрут і правила, а запити без правила пересилає на справжній хост.

Обмеження маршруту на весь хост (`/*`): через диспетчер підуть статика і WebSocket; завантаження буферизуються цілком, WebSocket не підтримується. Тому вказуйте префікс API.

## 6. Map Local у деталях

- Правило на хост мапить `https://<host>/*` у каталог `~/charles-mocks/<host>/`. Є файл за шляхом запиту — Charles віддає його; немає файлу — запит іде на сервер.
- Файл перечитується на кожен запит, правки видно одразу.
- **Статус завжди 200**, query string і HTTP-метод **ігноруються**: усі варіанти одного шляху отримують один файл. `/users` і `/users/42` одночасно замокати не можна.
- Файли без розширення Charles віддає як `text/plain`; `mock_setup_host` додає правило Rewrite, яке міняє його на `application/json` для цього хоста (Rewrite застосовується і до відповідей Map Local).
- Відповідь із мока несе заголовок `X-Charles-Map-Local: <шлях до файлу>`, а в нотатках запису Charles — «Mapped to local file».
- Якщо для того самого шляху заведені і Map Local, і Map Remote, приберіть файл Map Local (`mock_remove`), інакше запит не дійде до диспетчера.

## 7. Вимоги до Charles

- **Web Interface** увімкнений (Proxy → Web Interface Settings), логін і пароль збігаються з `CHARLES_USER` / `CHARLES_PASS`. Anonymous access не вмикайте. Через Web Interface charles-mcp читає сесію і вмикає інструменти.
- **SSL Proxying** увімкнений для хостів API (Proxy → SSL Proxying Settings), сертифікат Charles встановлений на пристрій. Без цього Charles бачить HTTPS лише як тунель до хоста і не знає шляху запиту, тому правила зі шляхом (Map Local, Map Remote з `/api/*`) не спрацьовують.
- **Корпоративні сертифікати**: диспетчер сам ходить на справжній сервер для запитів без правила і для правил patch. Якщо сертифікат сервера випущений внутрішнім центром, у `routes.json` поставте `"verify_tls": false` для цього маршруту.
- **Розмір сесії**: кожен live-запит вивантажує всю сесію Charles. Очищайте сесію перед сценарієм; сесія на кілька гігабайтів робить інструменти непридатними.

## 8. Якщо правило не спрацьовує

Почніть з `mock_dispatcher(action="verify")`: він стукає в диспетчер напряму, а потім по одному URL на кожен маршрут через Charles, тож відокремлює «правило неправильне» від «запит не дійшов до диспетчера» ще до читання таблиці.

| Симптом | Причина і що робити |
|---|---|
| Відповідь прийшла без `X-Charles-MCP-Rule` | Charles не відправив запит у диспетчер: інструмент Map Remote вимкнений (`mock_dispatcher start` вмикає його), правило не збережене (у вікні Map Remote його немає — натискали Cancel замість Done), не збігся хост, шлях або протокол, немає SSL Proxying для HTTPS |
| Charles відповідає 503 «Name lookup failed» | Map Remote не застосувався, і Charles пішов на вихідний хост; див. рядок вище |
| Мапінг видно у вікні Map Remote, але нічого не маршрутизується | Charles не запускали після запису мапінга: він завантажує мапінги лише під час старту. Закрийте і запустіть Charles, тоді `mock_dispatcher(action="verify")` |
| `X-Charles-MCP-Rule: passthrough` | Запит дійшов, але жодне правило не підійшло: перевірте шлях, метод і значення `action` (`mock_discover_variants`), чи не вимкнене правило |
| 421 від диспетчера | Хост або шлях не покритий маршрутом у `routes.json` — `mock_route_setup` |
| 502 від диспетчера | Диспетчер не достукався до сервера: мережа/VPN, тайм-аут (`CHARLES_DISPATCHER_TIMEOUT`), сертифікат (`verify_tls`) |
| Усі запити до домену падають | Map Remote увімкнений, а диспетчер не запущений — `mock_dispatcher(action="start")` або вимкніть Map Remote |
| Заголовок `X-Charles-MCP-Warning` | Правка не застосувалася (тіло не JSON або шлях у правці не знайдено), відповідь віддана без неї |
| Правка конфіга «зникла» | Конфіг писали при запущеному Charles, і він затер його на виході — повторіть за розділом 4 |
| Import файлу у вікні Map Remote видає помилку `Class.isInstance ... is null` | Імпорт такого файлу в Charles 5.2.1 не працює; використовуйте `apply=true` або ручне введення |
